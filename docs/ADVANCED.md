# Advanced Capabilities (v2 extension)

This document describes the performance, intelligence, and learning layers added on top of the base architecture.

## 1. Streaming Response System

`POST /api/chat/stream` returns a Server-Sent Events stream:

```
data: {"event": "intent", "data": {...}}
data: {"event": "token", "delta": "Hello"}
data: {"event": "token", "delta": ", world"}
data: {"event": "end", "reply": "Hello, world"}
```

The frontend uses `streamChat()` (`frontend/src/api.js`) to render tokens as they arrive. Pure-chat intents stream directly from the general NIM model (`AsyncOpenAI.chat.completions(stream=True)` → `client.stream()` in `backend/nvidia/client.py`). Complex flows still run the full pipeline and stream the synthesized reply for UI consistency.

## 2. Caching Layer

Two-tier cache (`backend/cache/`):

| Layer | Hit condition | Latency |
|-------|--------------|---------|
| **exact**    | SHA-256 of the prompt matches | sub-ms (memory) / ~1 ms (Redis) |
| **semantic** | NIM embedding cosine ≥ `CACHE_SEMANTIC_THRESHOLD` | ~50 ms |

Backends (interchangeable via `CACHE_BACKEND`):
- `memory` — in-process LRU+TTL (`MemoryBackend`)
- `redis`  — `redis://localhost:6379/0` (`RedisBackend`, gracefully degrades to memory if Redis is unreachable)

Stats: `GET /api/cache/stats`. Invalidation: `POST /api/cache/invalidate {"namespace": "chat-reply"}`. The orchestrator uses `cache.wrap(...)` so the call site stays clean.

## 3. Vector Memory

`backend/vector/store.py` keeps an embeddings matrix persisted to `data/vectors.npz`. Two backends:

- `numpy` — pure-numpy matmul (default; up to ~50 k entries)
- `faiss` — `faiss-cpu` `IndexFlatIP` (optional; `pip install faiss-cpu`)

Every `remember this <X>` call mirrors into the vector store and **auto-links** related memories on insert (`find_related`, threshold 0.6). Recall via `POST /api/vector/search`.

## 4. Context Optimization

`backend/memory/context.py`:
- `summarize_old_turns()` — when chat exceeds `SUMMARIZE_AFTER` turns (default 40), the oldest half is replaced with a single `[summary]` message generated by the long-context NIM model (Kimi by default).
- `build_context()` — at prompt time, injects top-K semantically relevant memories *and* the most recent turns. Prompts stay small even after thousands of turns.

## 5. Internet + Deep Search

`backend/search/web.py` — three backends, picked by `SEARCH_BACKEND`:
- `duckduckgo` (no API key, HTML scrape)
- `tavily` (`TAVILY_API_KEY`)
- `serper` (Google via `SERPER_API_KEY`)

`backend/search/deep.py` — multi-step research loop:

1. Reasoning model produces 1–3 search queries.
2. Each query → web search → fetch top URLs → clean text.
3. Refine model decides if more queries are needed (`done?` / new queries).
4. Loop up to `DEEP_SEARCH_MAX_STEPS` (default 4).
5. Synthesizer model produces a cited answer with `[1]`, `[2]` references.

API: `POST /api/search/deep {"question": "..."}`. Skill: `deep_search`.

## 6. Auto-Learning (Passive Layer)

`backend/learning/passive.py` — every completed turn records `{intent, strategy, model, skill, latency, ok}` and updates:

- **Router scores** — model latency + quality (already used by the smart router)
- **Strategy preferences** — per-intent preferred strategy (e.g., `research` → `deep_search`)
- **Skill weights** — boost auto-selection of skills that succeed

Exponential decay (`LEARNING_DECAY`, default 0.9) prevents stale data from dominating. State is persisted to `data/learning.json`. **No version bump** — passive learning is the "improve internally without changing version" layer requested in the brief.

## 7. Intent Prediction

Before planning, the fast NIM model classifies the message into `chat | command | code | research | system | memory | upgrade | search` with a strategy hint. Cached for 5 minutes (semantic match for paraphrases). The orchestrator dispatches:

| Strategy | Behavior |
|---|---|
| `direct`      | Run the suggested skill, no plan |
| `deep_search` | Multi-step research loop |
| `debate`      | Coder ↔ Reviewer ↔ Optimizer iterative loop |
| `plan`        | Classic Planner → parallel steps |

After confidence ≥ 0.8, the passive learner can override the strategy with the historically best-performing one for that intent.

## 8. Agent Collaboration

`backend/agents/collaboration.py` implements `debate(task)`:

```
Coder v1 → Reviewer (score) → if score ≥ 8.5: stop
                          ↓
                       Optimizer rewrites → Coder v2 → Reviewer …
```

Up to `MAX_ROUNDS` (default 3); the highest-scored version wins. Endpoint: `POST /api/agents/debate`. Cross-review: parallel independent reviewer instances (`collaboration.cross_review()`).

## 9. NVIDIA Model Intelligence

- **Auto-discovery**: on startup with `NIM_AUTO_DISCOVER=true`, the client pulls `/v1/models` and merges new ids into the registry, inferring tier from the name.
- **Parallel race**: `NIMClient.race(models=[...])` sends the same prompt to multiple models, returns whichever finishes first. Useful when latency matters more than quality consistency.
- **Best-result merging**: the debate loop and `collaboration.cross_review` already implement N-way comparison.

## 10. Observability

| Endpoint | Purpose |
|----------|--------|
| `GET /api/cache/stats`        | Cache hit rates, writes |
| `GET /api/learning`           | Passive learner snapshot |
| `GET /api/vector/size`        | Vector store size |
| `POST /api/intent`            | Try the intent classifier |
| `POST /api/search/web`        | Web search (no LLM) |
| `POST /api/search/deep`       | Full deep search with citations |
| `POST /api/agents/debate`     | Run a debate session |
| `GET /api/models/live`        | Live `/v1/models` discovery |

WebSocket channels added: `cache`, `intent`, `strategy`, `search`, `debate`, `learning`.

## Performance Profile

Typical perceived latencies on a free NIM tier:

| Path | First token | Total |
|------|-------------|-------|
| chat (cached, exact) | <50 ms | <50 ms |
| chat (cached, semantic) | ~100 ms | ~150 ms |
| chat (streamed, miss) | ~600 ms | depends on tokens |
| direct skill | ~400 ms | varies (terminal: instant; web fetch: ~1 s) |
| plan (classic) | ~1.5 s | 2–6 s |
| debate (3 rounds) | n/a | 8–20 s |
| deep_search (4 steps) | n/a | 15–40 s |
